# v0.6 工具面比较与审批约定

依据 2026-10-16 的《mcp sentinel 下一阶段研发与商业验证计划书》。本决策落实 W01—W04 与 W06 的共同契约；进度与验收见 execution-status.md。

## 采集与指纹

覆盖 name、title、description、inputSchema、outputSchema、annotations 六个字段。SDK 未暴露或当前模型未纳入的字段不在检测承诺中。基线及快照保留已采集字段的原文；指纹单独规范化，不修改实例数组顺序或实例字符串。规范化版本为 2。

Schema 对象键排序，required、type、enum 外层排序；oneOf 保留分支次数。实例值与未知扩展仅排序对象键。涉及位置引用时保留数组结构，避免重排改变引用含义。结构差异未被规则解释时必须阻断，即使同时存在标题等已知变化。

## 基线与目标

基线格式提升为 3，严格拒绝未知版本、重复 JSON 键、错误字段类型、内容与指纹不一致。目标标识来自配置的稳定别名、传输类型与非敏感端点或启动命令；不使用服务自报名称认证目标，不保存请求头、环境变量值或完整命令参数的摘要。

旧格式可能已丢失 oneOf 重复项和 enum 实例顺序，不能无损迁移。保留旧文件，从可信服务重新采集、审阅后建立新基线，不能在普通 CI 中自动 lock。

## 审批

审批整个已审阅快照，必须同时提供 `--expect-baseline` 与 `--expect-surface` 两个完整 SHA256。普通 scan 的 JSON 报告提供这两个值。重新采集的工具面或当前基线与任一预期不符时拒绝写入。

写入使用同目录临时文件、回读校验及原子替换。不支持原子替换时明确失败。审批写入前在同一目标的协作锁中重新检查基线，拒绝并发覆盖。该锁只协调本工具的写入；有权限直接篡改文件者仍受仓库权限和代码审批约束。

审批记录绑定目标、旧工具面和新工具面；历史记录是审计依据，不可在不同上下文自动批准相似变化。批准基线不会清除静态风险。

## 报告与失败

人读输出统一转义服务及路径中的控制字符。JSON 保存序列化后的原始字段，报告最终退出状态、采集状态、错误类别及完整指纹。任何应检查目标失败均不能整体成功。

快照可离线检查；脱敏仅移除声明的文本字段，不保证删除所有敏感数据。脱敏文件不能作为基线或审批证据。在线扫描会启动 stdio 进程或访问 HTTP，规则比较本身不需要模型服务。
