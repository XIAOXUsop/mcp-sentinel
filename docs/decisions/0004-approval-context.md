# 批准绑定已审阅的具体快照

仅给出 --accept-changes 会把采集时的最新状态当成已获用户批准，审阅与执行之间发生变化时可能批准错对象。因此要求 --expect-baseline 与 --expect-surface 两个完整指纹，同时核对配置目标身份。

写回前在协作锁内再次读取基线。其他本工具进程已替换基线时拒绝覆盖；不支持原子替换时明确失败。历史审批绑定目标及前后工具面，不能在另一个快照上下文自动复用。

选择批准完整快照，并在报告中保存全部变化；暂不支持选择单条变化后暗中推进完整基线。已有仓库权限能够重写全部证据的人仍由代码评审和分支权限约束，完整性摘要不承担来源认证。

验证入口：TrustRegressionTest 的历史审批、协作锁和失败写入样例；OfflineWorkflowTest 的过期快照、目标不匹配和批准闭环；CliEndToEndTest 的线上采集与再次变化。
