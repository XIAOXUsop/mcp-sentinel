# 真实依赖告警核实

当前真实告警未核实，稳定发布仍阻断。测试中的合成告警仅验证读取/拒绝逻辑，不证明实际仓库已无告警。

访问条件：仓库的 Dependabot 告警读取权限。发布工作流读取已配置的 `PREFLIGHT_TOKEN`，本地入口只读取环境变量 `GH_TOKEN`。令牌不能写入聊天、命令参数、公开文件或日志；普通仓库/Actions 读取权限不代表能够读取告警。

访问条件就绪后使用受信环境执行：

```text
python scripts/fetch_dependabot_alerts.py --repository XIAOXUsop/mcp-sentinel --output alerts.json --receipt alerts-complete.json
```

取得完整清单与回执后，核对仓库、采集时间、查询条件、分页条数、清单摘要和候选 SBOM。默认 HIGH/CRITICAL 阻断；其他等级记录处置依据。访问失败、异常结构、重复告警或分页未完成都保留失败，不建立“零告警”证明。

回执 v2 包含 UTC 时间、采集器版本、仓库与执行身份。保存回执最多接受 24 小时年龄和 5 分钟未来时钟偏差，这是本项目策略；旧版回执不能用于新的稳定准入。正式发布每次现场重新采集，并要求回执来自同一运行和尝试编号。

`release_preflight.py` 同时需要完整候选证据、预期仓库、标签及默认分支。它首先检查用户的发布决定；既有阻断没有解除时应拒绝。`--alerts-optional` 不允许跳过检查；稳定入口也不接受 `--skip-behind-check`。

本轮不改变用户选择的等待安排。未来具备访问条件且用户解除发布阻断后，沿正式工作流采集和验收；发现依赖问题时先修复并形成新的候选，不复用旧 JAR 作为新版本。
