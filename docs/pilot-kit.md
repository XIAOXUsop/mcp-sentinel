# 用户访谈与试点准备

以下是执行材料，尚无真实访谈、试点或付费结果。不得用测试夹具、生成样例或口头称赞替代用户证据。

## 访谈记录模板

每次记录日期、团队类型、使用者与审批者、是否有预算负责人，以及是否允许保存脱敏材料。请回答：

1. 最近一次 MCP 工具声明变化是什么，谁发现，谁批准？
2. 当前接入多少服务，分别属于哪些角色与环境？
3. 漏掉或误报一次变化，会导致什么具体工作？
4. 目前用什么检查或网关，哪里仍需要人工？
5. 安装、凭据、CI 和误报中，哪个最妨碍持续使用？
6. 若接入服务或持续维护收费，谁决定、预算时间与条件是什么？

目标为 10 次有效访谈；记录具体经历与已有流程，不把“愿意看看”计作采购意向。联系人及发送渠道由维护者选择，未自动联系任何人。

## 两周试点协议草案

每个团队选 1—3 个服务，指定接入负责人和目标别名，约定所需权限及可以保存的证据。第 1 天记录首次接入耗时与人工帮助；之后记录扫描次数、需审阅变化、误报、工具故障、被绕过的门禁和处理时间。第 7、14 天收集继续使用的具体理由或停止原因。

使用成功信号：至少 2 个团队连续 10 次 CI 没有工具自身故障，并能独立解释一次变化。商业信号：付费试点，或包含预算负责人、采购条件及时间的明确意向。样例数量与社区星标不计作商业信号。

## 可报价服务范围

首个服务包可限定为配置审阅、最多 3 个目标接入、基线建立、一次培训、两周兼容性修复。持续维护另约响应窗口、版本范围及退出方式。报价前先记录实际投入与用户支付意愿，不预设未经验证的市场价格。

试点反馈以 Issue 形式记录触发条件、预期／实际结果、脱敏复现及验收。未获许可的快照不公开，也不默认收集遥测。只有真实反馈发生后才启动 W12 的对应修复项。
